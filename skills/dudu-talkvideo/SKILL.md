# DuDu-talkvideo

<!-- INSTALLED_PROJECT_ROOT -->
本Skill是公开版通用IP视频制作入口。安装时必须保留整个仓库，不能只复制本目录。通过Skill真实路径（解析软链接）向上两层定位项目根；Windows指针安装则读取同目录project-root.json中的projectRoot。项目根必须含scripts/workflow.py、runtime/renderer.js和brand/style-lock.json；缺失时先按仓库README与docs/INSTALL.md安装完整项目。

先读项目PROJECT_STATE.md与brand/style-lock.json。用项目的dudu.py或./dudu执行命令，自动采用本项目.venv，不依赖作者电脑或其他Skill。未完成安装时先运行scripts/bootstrap.py，不要猜测本机专用路径。默认薄荷绿小方块；折纸鸟、小轨道和六套配色全部可用。选择主题、角色和三种基础版式时读项目 references/themes.md。只修改新一期复制的 brand/style-lock.json，不覆盖其他已有项目或已安装 Skill。

## 已定的风格与判断

- 默认 theme=mint、mascot=block，使用薄荷绿小方块与浅色流程版式；保留分栏讲义、深色路径两类模板及其他五套配色。用户未指定时直接用默认，不要求重新选风格。默认1920×1080、30fps，时长随完整旁白。
- 先按完整讲述段落选择主画面，再用段内聚焦、圈注或操作推进。五类主画面是：关系图解、真实操作、原始证据/成果、IP 情境、IP＋少量文字/图形混合讲解。IP 情境也可介绍工具、作类比、连接前后内容，不能只当情绪插图。讲述任务改变时再换主场景；长段不能始终挂同一张头像卡，也不按短语或固定秒数切镜。A/B-roll 按叙事作用区分。
- 开工先确认出镜方式（2026-11-03最新要求）：新一期在选动画、语义分镜、关键帧前，问清“本期使用通用 IP小人物，还是真人出镜？”。当前请求已明确时直接记录，不重复问；不能仅按有无真人素材自动选择，也不自行从真人回退IP。使用 `presenter` 记录本期选择原话与出处；缺真人素材时列待补。同一条视频不混用真人讲述者与IP。IP版围绕人物/道具/图解的运动组织注意力；真人版围绕原口播景别、视线、手势与B-roll交接设计，不套几何IP口型、强调上移或卡通弹跳。详见项目 `references/presenter-and-camera.md`。
- 左下角IP是独立讲述层。正文画面、真实录屏和图解可同时保留它；挡信息时移动、缩小或隐藏。人物主场景中不再叠放重复角落头像。
- 默认使用同一几何角色的闭嘴/小口/大口三态SVG，停顿闭嘴。嘴形只由本期旁白包络驱动；语义重点可轻微上移和放大再回位。这是有限嘴形动画，不声称音素级口型。用户指定定帧表情或局部动作时，按本期要求冻结其他部分。
- 声音以用户当次提供的成品录音或指定音色为先，刘飞只是默认预设。指定本人克隆音色时核对真实 Speaker ID 与可调用状态；要先听第一段就先做试听，不替换成默认音色。多段录音依实际内容和稿件核对顺序，保留原件，不重复 TTS。凭据仅从本机私有配置读取，不进入项目交付或 Git。
- 新一期默认仅旁白，不自动添加背景音乐或音效，不固定沿用旧样片曲目或音色。`audio-request.json` 初始music=false、sfx=false、cuePolicy=none。需要时按本期用户要求或用户认可的声音方案显式启用，再按动作、叙事与实际时间选材/落音；不因动画存在而自动开启。已有完整混音不重复铺底。

## 制作与审查

1. **出镜确认、接稿与取证。** 保存原稿，用 `scripts/workflow.py new` 建独立一期，先确认本期IP或真人，用 `presenter` 记录；未确认不能生成语义分镜。教程核对实际结果、新闻查原始出处和日期、观点准备案例。记录来源与缺素材，生成示意不能冒充真实操作或证据。
2. **语义分镜与声音意图。** 按含义编排 `storyboard.json`，记录原句、目的、主画面、素材、重点、人物和读完所需时间；每镜 `cameraPlan` 写明主体、景别/构图、运动和依据。`soundPlan` 只说明动作是否需要声音、优先本地库候选、缺口及留白，不将估时当正式落点。运行 `semantic`，使用本项目增强工作台交付HTML。此时预估时间明确为预估，缺素材明确标待补。
3. **等待用户同意。** 这是用户明确要求的节点。用户没有同意该版语义分镜前，不生成本期关键帧或进入正式配音/渲染。网页意见、助手自检、批准本Skill及历史一期均不能替代本期批准。收到真实同意后，用 `approve --quote ... --evidence ...` 记录原话和出处，绑定分镜SHA。语义实质改动须展示新版再获同意；时间校准/生成帧写sidecar，不改获批源文件。
4. **旁白时间、音效选材和实际关键帧。** 用本期旁白及字级时间对齐场景与动作，补齐真实素材。音效按需从现有本地库与经典试听选择，关闭音效的本期跳过选材。声音设计随分镜确定：纸条/媒体入场可用paper，圈注/核对可用tick，确有灵感发现才用idea；需要精确安排时在该镜头填soundCues，以真实词锚点或已核对时间触发。保留独立旁白、音乐、音效和最终混音；IP嘴形只取旁白包络，真人保留原片口型。实际渲染每镜头足够说明结构/重点/结果的关键帧，运行 `review`，在同一个工作台切到关键帧阶段。不能用AI概念图或未实现示意冒充实际关键帧。
5. **完整动画、精确落音与反馈。** 动画动作点确定后，校准音效起音/尾音、裁剪与增益，试听动作和最终混音；单独好听不等于混入旁白后合适。全片任务须覆盖全部已批准段落，不能把结尾试片或关键帧当成全片完成。用户要求按网页意见修改时，先读取项目保存的意见与附件、定位当前版本和镜头，再局部返修；旧版未同步时再从浏览器导出。既有约定未设额外强制审批点；按当前指示继续连续动画、成片预览与交付。关键帧HTML保留逐镜头意见；未批准的语义变化不得绕过第3步。
6. **验收与交付。** 先核对交付覆盖范围和播放器实际引用版本。核对事实和画面、字幕可读性、头像遮挡、静默闭嘴、强调与回位，再检查连续运动、音频/字幕/帧数/完整解码。交付MP4、SRT、本期工程入口，保留原素材及修改记录；多声音版本共用一个画面母版，再分别封装；仅技术通过不声称完整人工审看完成。公开发布需要用户当次授权。

用户明确指定局部修改或要求展示已批准样片时，只做对应工作；不让固定流程强迫重做已批准内容。画面局部返修优先规划“修改范围＋前后各 2 秒”，按编码与时间条件复用旧片；不兼容时再扩大范围或回退全片渲染，并说明实际方法。只有声音变化时复用画面，只有画面变化且时间不变时保留原声音与字幕。

- 真人出镜时完全替代 IP；补录无对应人物画面时，可缩小为边角陈述窗，不声称逐字口型同步。
- 装饰性小字默认删除；用户明确指定的章节标签按范围保留。
- 逗号或句号形成字幕边界，每句完整展示，末尾不加普通标点。

## 工作台与执行入口

工作台必须使用本项目 `workbench/template.html`（源于用户“做视频”项目增强 v9-A）；保持三栏结构、顶部折叠、播放控制、已删除视图、全局撤回、反馈编辑、附件持久化、历史和即时保存。当前反馈区不显示审看状态按钮或附件选择按钮；图片、GIF、SVG、文件和文件夹通过粘贴或拖入添加，缩略图显示在输入框上方。直接打开未绑定模板时只能显示说明并转到有数据的 `/review/` 页面，不能把模板文件冒充本期页面。不要从其他 Skill 原始工作台重新搭建。语义与关键帧沿用同一镜头 ID/项目命名空间；新增排版仅为必要审查信息。

精确编辑提案UI已保留，但对象源未接通时按钮禁用，不能宣传已经能直接改任意画面。通过本项目服务打开的工作台会自动将意见、附件和操作历史保存至本期 `feedback/latest.json`、`feedback/attachments/`、`feedback/revisions/`，助手优先直接读取；原浏览器保存与导出仍保留。首次升级需在原浏览器打开一次以迁移旧记录；检查项目保存状态与冲突备份，静态旧页或保存失败时才需浏览器导出。HTML快照本身不包含全部实时意见。
