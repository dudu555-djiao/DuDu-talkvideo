# 一期视频怎样从文案走到三版成片

2026-10-25，根据《我用 Codex 复刻视频风格｜Skill 分享》的实际制作与返修整理。案例用于解释决策和验证方法；不附本人录音、私人意见或第三方截图。本期约 3 分 13 秒、6 个讲述段落，采用当时的频道自有风格。该私人角色不在当前公开版中；公开版使用通用几何角色。

## 本期实际走过的流程

| 环节 | 本期做了什么 | 以后保留的方法 |
|---|---|---|
| 文案整理与事实材料 | 补齐频道告别、Skill 安装说明及提示词节选；根据新截图把赞数表述改为“两万多赞” | 保留原稿，工作稿单独修改；真实材料优先于旧稿里的数字 |
| 语义分镜 | 按讲述目的安排 6 段，确定对象、素材、主画面和 IP 职责，交三栏网页审看 | 新稿先语义 HTML；实际用户同意绑定本版分镜指纹 |
| 配音来源落定 | 前期核对豆包 CLI 和本人音色，最终采用用户交付的 5 段成品录音 | 成品音频优先；确认后停止重复 TTS，不把“配置有密钥”写成“指定克隆音色已可用” |
| 原音顺序与时间 | 根据完整稿核对后半段，把 Skill 安装说明放在个人观点与告别之间，保留原速与停顿 | 多文件按实际内容对稿，记录切片映射，不能靠文件名排序 |
| 字幕与动作锚点 | 形成 116 条字幕、6 段时间轴；词级位置来自本地自动估计并校对重点 | 标明时间来源，估计词戳不能冒充服务原生字戳；同一最终音轨驱动字幕、口型和动作 |
| 素材与真实关键帧 | 真实截图支撑事实，工作台素材讲操作，IP 插画讲情境，代码图解讲关系；从实际实现取帧 | 生成插画不能冒充实际界面；语义阶段与关键帧阶段共用镜头 ID |
| 全部动画 | 从曾经只完成结尾预览，纠正为覆盖全部 6 段的连续动画 | 关键帧和短预览是中间产物；用户要全片就检查整条内容覆盖 |
| 画面迭代 | 增强开头的入场与聚焦，调整框线；制作安排先用 IP 情境，结果阶段再用真实工作台；长结尾交替情境和图解 | 根据讲述任务选择主画面，不一味贴头像，也不按几个字切一个场景 |
| 网页反馈 | 导出意见与附件，归档旧版，按镜头及时间修正，再更新真实关键帧与审片引用 | 网页是持续审看入口；HTML 文件本身不能替代浏览器实时意见的导出 |
| 声音设计与三版 | 同一画面配三种声音：纯配音、配音＋音效、配音＋音效＋配乐 | 音效跟具体动画；配乐跟叙事节奏；一条画面母版多次封装，不重绘三遍 |
| 最后一轮局部修改 | 两段工作台加聚焦/黄线；结尾固定所选笑脸，只让手小幅平滑摇动 | 指定只动一处就冻结其他部位；静帧与连续运动分别验收 |
| 交付与发布包装 | 完整三版 MP4、字幕、可继续修改的工程；另完成 3:4、4:3、16:9 封面与四平台文案 | 包装按用户需求另做，不等于自动公开发布视频 |

## 最重要的画面判断

五类主画面各承担一种工作：**关系图解**讲清结构，**真实操作**呈现过程，**原始证据/成果**支撑事实，**IP 情境**表达行为、判断与类比，**IP＋少量文字/图形**承接主讲与重点。IP 不只用来表达情绪，还能拿着对象介绍工具、通过行动作类比、连接前后话题。

按完整讲述段落选择场景，同一场景内用聚焦、圈注和顺序展开推进。讲完一个问题或叙述对象改变时再换主画面。角落说话 IP 是独立讲述层；人物已经占据主场景时，不叠第二个头像。具体规则见 [制作判断](../references/production-rules.md)。

本期参考 FredTalk 时，核对了实际预览与实现，再把对应的入场、聚焦和笔刷动作适配到当前工程。录屏放大与标注保持同一坐标变换、同一媒体时钟，避免黄线漂移、截掉句首或把真实过程重画成假界面。具体方法见 [动效与返修](../references/motion-and-revisions.md)。外部库的名称不代表本仓库内置了其全部组件。

## 声音如何安排

音效选择来自本机 VideoTalkCraft 声音流程，按纸片、笔触、输入和明确转场安排，缓慢推拉和挥手不逐帧加声。配乐按 9 个叙事区段调整密度，教程与输入处让出注意力，观点处留呼吸，告别收束，并按旁白包络避让。每版旁白使用同一来源与增益，分别保留独立音轨和混音。

声音验收必须如实区分：本期 36 条音效的独立在场检查通过；更严格的混音可闻性检查将其中 33 条标为 MASKED。本期保留较轻的提示声，并记录原因，不能描述为所有声音检查通过。机器计量、模型听检、抽样试听与人工完整连续听审也分别记录。详见 [声音与多版本交付](../references/audio-delivery.md)。

## 最后一轮怎样省下全片重渲染

基准成片共 **5791 帧，1920×1080、30 fps，193.033333 秒**。修改区间先增加前后各 2 秒，再向外扩展到兼容的 GOP 边界，合并相邻范围。新画面按全片时间绘制，未改区间复制既有视频流。

| 核验项 | 本期结果 |
|---|---|
| 重新绘制 | 1939 帧，约 64.63 秒画面 |
| 复用旧片 | 3852 帧，128.4 秒画面 |
| 减少 Canvas 绘帧量 | 66.52%，不是对所有机器的耗时承诺 |
| 关键帧 | 更新 9 张，复用 30 张 |
| 未改视频区 | 旧新解码帧 hash 全部一致 |
| 三种声音 | 各自 AAC 流与前一版一致，未重新编码 |
| 最终检查 | 完整解码、帧数/时长、拼接点前后和实际播放器通过；不声称完整人工全片听审 |

原来的方法是**整条画面绘制一次，再封装三个声音版本**，也不是绘制三遍。新的局部方法适用于时间轴不变且编码可兼容的返修；改了整片时长、全局样式或无法可靠拼接时，扩大重绘范围或回到全片渲染。

本仓库提供 `plan_partial_render.py` 规划工具和 `mux_audio_variants.py` 复制封装工具。前者不自动绘帧、不保证 GOP 一定可拼接，后者不自动混音。实际效果仍由 Codex 按本期内容实现并检查，不把这次专用脚本里的固定时刻用于以后的视频。

## 下一期直接沿用的顺序

**原稿与真实材料 → 完整段落的语义分镜 → 用户同意本版 → 最终配音与时间 → 按五类职责准备画面 → 实际关键帧 → 全部连续动画 → 网页反馈与局部返修 → 声音设计/所需版本 → 验收、完整交付及按需包装。**

这次更新不改变 D 品牌默认、安装方式或增强三栏工作台；也不把本期黑框、特定手摇参数、具体音效数量和三版交付变成所有新片的强制模板。
