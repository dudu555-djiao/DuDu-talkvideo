# DuDu-talkvideo 制作判断与验收

用户于2026-10-24确认，配合brand/style-lock.json和实际认可样片使用。A/B/C/E等早期风格只是历史。此前对标视频是分段观察，不声称看完该作者全部作品，也不声称知道其后台制作技术。

## 主画面怎样选

A-roll承担主要叙述；B-roll补充展示、解释或证明。这个频道的IP主持可作A-roll，教程的连续实操也能承担主叙事。Remotion、Canvas、录屏是制作方法，不是A/B分类标准。角落说话头像是独立讲述层，不决定主画面的A/B身份。

| 此句的任务 | 优先画面和素材 | IP参与 |
|---|---|---|
| 展示成果/承诺效果 | 本期真实产物、可见前后差异 | 轻反应，给成果留面积 |
| 教操作 | 真实输入、关键点击、状态变化、结果 | 正常说话；避开光标/按钮 |
| 交代新闻或事实 | 原始发布、原文、数据与事件素材，保留名称日期上下文 | 与事实语气一致，不夸张喜剧化 |
| 解释因果、步骤、分类 | 图解/关系箭头/分组/对照，先交代对象 | 在关键词处克制强调 |
| 经历、困惑、情绪转折 | IP操作、思考、查看失败或灵感情境 | IP主场景，此时撤掉重复角落头像 |
| 举例或类比 | 具体作品、案例或明确的示意 | 不把类比/生成图包装成证据 |
| 个人判断 | 先证据，再关系与判断 | 在立场处承担表达 |
| 分章、总结、行动建议 | 简洁标题、已验证结果、下一步 | 适度反应或收束 |

先按完整讲述段落选主画面；一段可以包含多句话。段内通过聚焦、圈注或连续操作推进，讲清一个问题后再换主场景。不要随几个字在IP、图解和录屏间切换。不设固定A/B百分比或“每隔几秒切一刀”。当对象、状态、推理步骤或对比关系改变时换画面；连续操作保留因果顺序。同一张图可聚焦不同区域承载多句，但每次变化要有明确作用。

教程参考节奏：成果→条件→关键操作→输出验证→边界→复用方法。新闻：发生什么→出处日期→变化→影响→未知→判断。观点：问题→案例→机制→反例→结论。按内容使用，不机械凑齐所有段落。

## 五类主画面与 IP 的职责

本项目按叙事职责归纳五类：**关系图解、真实操作、原始证据/成果、IP 情境、IP＋少量文字/图形的混合讲解**。这是选画面的分类，不是要求每期五类凑齐；代码是实现方法，不另算主画面类型。

IP 主场景适用于经历、判断、工具介绍、类比、过渡和行动建议。让人物通过看、想、拿、指等行为与道具表达文意；不是只把大头像贴上去。需要证明软件确实运行时仍展示真实界面或结果。讲述关系时留在同一图解里逐步展开；讲操作时保留连续过程；先安排内容再看实际结果的段落，可以先用 IP 情境，讲到真实关键帧或结果时再切实际素材。

角落头像是独立讲述层，图解/录屏可以保留；人物已经成为主场景时撤掉重复角落头像。长总结段按语义单元组合情境与图解，避免整段只有静止头像和一条口号。开头依次建立对象和重点，让观众知道该看哪里。具体动效、录屏聚焦与人物局部动作见 [动效与返修](motion-and-revisions.md)。

## 每镜头必须清楚

原句及目的；观众此刻应看到的对象；主画面材料与来源/录屏入出点；聚焦区域；屏幕关键词；IP显示方式/情绪/强调词；本期实际时间；阅读停留；素材已获得还是待补。

素材优先：用户提供和已有授权资产→本期实际操作/截图/录屏→原始资料→直接相关案例。代码图解解释关系，新增IP图参考定版身份。没有真实结果就补采或明确标“下一步/示意”，不能伪造界面证明已运行。

旁白与屏幕字各司其职：字幕可完整表达口播；主画面保留关键对象与关系，不再次把整段台词抄成卡片。真实界面按关注区域裁切放大，保留足够上下文。

## 视觉与人物

浅色点阵是信息页基础，纸条、圈注、媒体框与手绘箭头用于组织内容。蓝边是可用默认，不要求每个画面都加；用户本期指定黑框、黑字或去框时局部覆盖，不反向改全局品牌。真实图片和软件画面保留原色。工作室只在人物情境需要时使用。标题是装饰字体，正文与字幕保持易读黑体。重要操作区可让头像退让。

默认人物基于同一张稳定胸像，只替换对齐的嘴部区域。三种嘴形闭口/小口/大口按约0.5秒有限循环，真实人声包络控制活跃区间。停顿闭嘴，声线冻结；背景音乐不能驱动嘴形。没有用户新要求就不随意改脸、发型和衣服。

重点出框使用固定圆框，人物轻抬约30px、少量放大，头发在前景覆盖上缘；持续时间依语义和配音配置，强调后回位。普通词音量变大不等于值得出框。眨眼/惊讶等可按内容补充，但不是当前已完成的独立表情资产。

用户指定固定表情或只动手时，关闭对应段自动口型、眨眼与其他动作；以选定源帧为基准验证静止区域，见 [局部人物动画](motion-and-revisions.md)。

## 默认声音

正式视频沿用52秒参照的96 BPM轻柔felt背景乐与稀疏的paper/tick/idea音效。音乐低音量铺底、首尾淡入淡出；纸条和媒体入场可用纸声，圈注/核对用轻点，明确灵感发现用三音提示。音效随本期动作/实际语音时间重新落点，不照搬参照秒数，不每句话都加声。独立保存旁白、音乐、音效、混音和事件依据，口型始终只读人声。口型测试或明确纯旁白时关闭音乐和音效。

## 两阶段审查

1. 语义HTML：只展示画面计划、素材状态与IP安排；时间是预估，不能假装已有实际帧。
2. 用户明确同意本版后记录SHA；之后才生成本期声音与实际关键帧。
3. 关键帧HTML：由真正的渲染实现取帧。每镜头通常选结构建立、重点变化、结果三个有意义的状态；没有变化的短镜头不强凑三张。
4. 同一镜头ID贯穿意见、资产、时间和关键帧。语义实质变更重审；不影响内容的时间校准/技术实现放sidecar。
5. 后续反馈局部返修。关键帧阶段提供审看入口，未另设每次都必须点确认的额外流程。

增强三栏工作台保留附件、文件夹、文件下载、段落删除/撤回、全局撤回、历史、版本、即时保存、刷新恢复、导出与输入性能改进。精确对象编辑须有对应对象源，未连接时明确禁用。HTML勾选或助手内部检查不代替用户在对话中对语义分镜的同意。

## 完整制作与局部返修

全片任务覆盖全部已批准镜头，检查开头、中段、长总结和告别，不能只做最后一段。用户直接提出局部修正时锁定范围，先保存网页意见与当前版本；保留稳定镜头 ID、批准源文件和历史。细节按 [局部渲染流程](motion-and-revisions.md) 执行。多声音版本按 [声音交付](audio-delivery.md) 共用画面母版，避免重复绘帧。

## 验收

- 内容：画面展示的对象和状态确实支持该句；事实/推断/观点/示意分清，教程结果可核对。
- 视觉：匹配当前品牌参数；屏幕字读得完；圈注不压字；人物不挡关键区域；新增图片身份稳定。
- 人物：局部嘴形无跳脸；停顿闭嘴；声线静止；强调时刻正确，出框和回位自然。
- 动态：先呈现对象，再聚焦/圈注；操作有因果。静帧和连续运动分别检查，不能以截图代替观看动画。
- 声音：本期字幕/声音配套，读音/自然停顿/重点一致，音乐让位旁白；不每次张嘴加音效。
- 技术：资源/字体加载，重复寻帧确定性，尺寸、fps、帧数、音轨、字幕范围，完整解码。适用时全帧扫描异常。技术验收不冒充人工完整试听。
