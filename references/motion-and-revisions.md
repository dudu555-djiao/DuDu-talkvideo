# 动效选择、网页反馈与局部返修

制作新画面或修改已有成片时读本文件。主画面判断见 `production-rules.md`；声音版本见 `audio-delivery.md`。以下是制作方法，不表示所有效果已成为通用渲染器内置组件。

## 按讲解任务选动效

先写清「观众应看哪里、理解什么变化」，再挑动画。开头可以按“对象出现→证据可读→重点放大”建立注意力；长观点段可以在完整语义单元间交替 IP 情境、关系图解和少量关键词。不要用整段静止头像替代讲解，也不要为了热闹让所有元素同时动。

| 讲解需要 | 合适动作 | 验收重点 |
|---|---|---|
| 看清网页某一段、按钮或结果 | 在同一真实画面内推近、平移、停留，再回到上下文 | 字能读；目标完整；不丢掉操作与结果关系 |
| 指认一句原文或一个输入框 | 黄色笔刷划线、圈注、局部遮罩 | 在原位置强调，不能横线压住文字或指错对象 |
| 比较两种状态 | 对齐并列、顺序揭示、同位置替换 | 明确什么变了，不能靠闪烁让观众自行猜 |
| 说明因果或步骤 | 对象先建立，连线/分组/步骤逐项展开 | 同一图中推进，保持阅读顺序 |
| IP 表达、过渡或告别 | 语义手势、轻微入场、克制的局部动作 | 角色身份稳定，动作幅度与情绪一致 |

用户指定 FredTalk 时，先查当前可用 `fred-remotion-output` 的目录，再看候选实际预览与实现，记录“文案锚点→候选→选择理由→本期实现→实际取帧”。本期曾采用 INT01 / NewsBrushFocus 的同画面聚焦与笔刷逻辑；这是例子，不是所有录屏的固定模板。适配到本项目 Canvas/Remotion 实现，保留 D 风格与增强工作台。组件名称、源码或预览未实际核对时，不声称已复用某个组件。

FredTalk 是按需参考，不是安装 DuDu-talkvideo 的强依赖；目标机器没有该库时，直接以本表的效果要求独立实现，不编造库资产，也不从作者机器复制未授权的外部代码。

## 真实录屏聚焦

保留真实软件输入、关键操作、状态变化与结果。镜头推拉只是视图变化，不改变源视频的时间与操作因果。若素材由间隔截图编码，记录实际采集频率，不把导出 30 fps 称为原生 30 fps 录屏。

同一媒体及其标注共用坐标变换。可以在源图坐标里定义聚焦框，再统一缩放/平移；不要缩放截图后把黄线留在旧坐标。先让对象可辨识，再画线强调，给阅读留足停留。检查缩放开始、最大聚焦、标注完成、回位和场景交接。

给左下角讲述 IP 留空间；蓝框不是每个媒体窗口的必需物。用户要求黑色或无框时在本期覆盖；真实素材本身保留原色。放大时不要裁掉句首、输入框边缘或实际结果，不能为了突出一个词遮掉原文意义。

## 固定表情，只动手

这是用户明确要求该动作模式时的分支，不改变默认说话 IP 的口型规则。

1. 保存用户选定帧，定位对应源姿态；冻结嘴、眼、头发、脸和身体，禁用该段自动口型、眨眼与换表情。
2. 只对手/必要袖口建立局部动作区域，稳定腕部支点，幅度从小开始，使用连续缓动。手与头发重叠时保护头发，不能跟着拉扯脸。
3. 可用已对齐的逐帧素材或平滑局部形变。逐帧不要切换成不同脸；网格或纹理形变要检查轮廓毛刺、三角缝、黑点、重影和腕部断裂。
4. 在入场结束后的相同构图中对多个时刻取帧，固定区域应无像素变化；再连续播放确认手势柔和。原有入场整体移动与稳定后的手部动作分开验收。

本期 ±1°、2.4 秒周期是一次小幅手摇的实测参数，不是所有角色的通用数值。

## 接收网页反馈

用户指示按网页意见修改时，读取当前版本、镜头 ID、意见正文、附件及其关联时刻。先导出原意见和附件备份，再整理本轮修改表：镜头、范围、要求、需保留项、实现位置、验证结果。保持项目命名空间和镜头 ID，刷新页面时不要清掉原意见或历史。

截图只是定位线索，先确认页面实际播放的是哪个成片；旧 `final.mp4`、新版本清单和播放器引用可能不同。技术回填写 `episode.json`、时间文件和关键帧清单；获批的 `storyboard.json` 不因取帧或换代码而重写。用户已明确要求的局部视觉修正可直接执行，不额外发明一次审批。

## 局部渲染与拼接

适用条件：已有可用成片，本轮改变局部画面，且旁白、字幕时间、总帧数、fps、画幅与未改部分素材保持一致。若改变片长、全局字体/颜色/滤镜，先扩大影响范围；全局影响可能需要全片重渲染。

若用户把“仅修改处及前后缓冲”限定为严格上限，候选 GOP 扩展不能自动扩大新绘范围：先区分实际新绘与仅用旧帧重编码的边界，争取只重编码必要衔接；仍无法满足时说明具体限制，不能无声回退全片。用户已明确允许回退时再按该授权执行。

1. **锁定基准。** 记录旧成片、当前代码/素材/时间文件的 hash，保存旧版。列出实际影响区间；阴影、转场、镜头回位等也计入范围。
2. **增加上下文。** 默认在每处影响区间前后各加 2 秒，裁到片头片尾，合并交叠区间。用户指定其他缓冲时以其为准。按帧数表示 `[startFrame, endFrame)`，不能用模糊小数拼片。
3. **规划边界。** `scripts/plan_partial_render.py` 读取真实媒体信息和关键帧，向外扩展到候选 GOP 边界，列出重绘和复用范围。它只生成计划，**不执行渲染，也不证明拼接安全**。关键帧标志并不独自证明是闭合 GOP。
4. **按全局时间重绘。** 本期渲染实现仍以全片时间寻帧，避免局部从零计时使口型、源录屏、字幕或动画错位。渲染中锁定代码与资产，不能边改边混入一条成片。
5. **验证编码兼容。** 核对 codec、分辨率、fps、像素格式、色彩范围/空间、时基、时间戳及编码头信息（H.264 的 SPS/PPS 等），确认边界能独立解码，避免开放 GOP 依赖旧帧。再尝试未改区间 stream copy 和拼接；不兼容则重编码必要边界/片段，仍无法可靠拼接再全片渲染。说明实际采用的方法与原因。
6. **复用声音。** 仅画面变更且时间不变时，沿用各版原音轨，不再 TTS、不再次归一化或剪录音。三版共用一个新画面母版。
7. **验证成片。** 完整解码；核对总帧数、时长、音画起点；逐一检查拼接点前后至少数帧与连续播放。对声称直接复用的片段，比对旧新解码帧 hash；对复制音轨比对流 hash。没做这项检查就不声称逐帧零差或音轨逐字节保留。
8. **同步审片入口。** 只更新受影响的关键帧，复用未改帧；清单绑定当前源码/时间指纹。确认播放器与下载都指向新版本。交付完整成片，同时记录本轮重绘/复用的区间、帧数及回退情况。

这些是制作约束与规划工具。当前通用 `./dudu render` 仍是全片渲染；不要虚构 `./dudu patch` 一键命令。本期专用渲染脚本若用于新片，必须先移除旧片路径、秒数和帧数。
